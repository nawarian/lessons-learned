You asked three questions:

  1. Must I decide the output length in advance?
  2. Can I provide a prompt?
  3. How does context window sizing work?

These cut to the heart of how diffusion models actually get used. Let me address each one.

1. Output Length: Yes, You Decide Upfront — But There Are Workarounds

Short answer: In a pure diffusion LM, you must set the output length before generation starts. This is the biggest practical difference from AR models.

Why? Because of how the process works

An AR model generates tokens one at a time. It can stop anytime (emit a stop token) or keep going. The sequence grows dynamically.

A diffusion model starts with a fixed-length canvas — all tokens at once — and iteratively refines them. The output length equals the canvas size. You can't grow it mid-generation because the denoising process is tied to the positions.

AR

Autoregressive: Dynamic Length

Prompt → "The capital of Brazil is"
Step 1: "Brasília"
Step 2: "."
Step 3: <stop>   ← model decides to stop here
→ Output: "Brasília." (2 tokens, unknown beforehand)

The model generates 2 tokens, then decides to stop. You never knew it would be 2 tokens — the model figured that out.

Pure Diffusion

Pure Diffusion: Fixed Length

Prompt → "The capital of Brazil is"
Canvas: [MASK] [MASK] [MASK] [MASK]   ← you decide: 4 tokens
Step 1: [·]   [·]   [·]   [·]         ← all noisy
Step 8: [Bras] [ília] [.]   [<stop>] ← all refined together
→ Output: "Brasília.<stop>" (exactly 4 tokens)

You chose a 4-token canvas. The model filled all 4. If you wanted 10 tokens, you'd need a 10-token canvas. You can't generate "just a bit more" without re-running.

Workarounds

Researchers have developed several strategies to deal with this:

Strategy How it works Used by Caveat
Over-generate & truncate Set canvas to max allowed length, generate, then truncate at the stop token Most pure diffusion LMs Wastes compute on extra tokens. Can't exceed canvas size.
Block-autoregressive Generate in blocks (e.g., 256 tokens) via diffusion, then chain blocks like AR. Each block depends on previous blocks. DiffusionGemma, Nemotron Adds some sequential dependency back, but blocks are diffused in parallel internally.
Iterative extension Generate N tokens. If more needed, append N new [MASK] tokens and continue diffusion. Research prototypes The new tokens don't benefit from the full diffusion process applied to the old ones.
Fixed-length domain Use for tasks where output length is predictable (summarization: ~150 tokens, translation: ~same as input). Production systems Only works for tasks with bounded output.
Practical advice: For your experiments, over-generate & truncate is simplest. Set canvas to 256 tokens, generate, look for <stop> or <eos>, trim. You waste some compute on the unused tokens, but it's simpler than block-autoregressive chaining.

2. Prompting: Yes, You Provide Input Text — Via Conditioning

Absolutely you can prompt a diffusion LM. The prompt is fixed (never masked, never noised) and the model attends to it bidirectionally — which is actually more powerful than AR's causal attention for understanding the prompt.

How it works visually

Input to the model (one row = one token position):

┌──────────┬─────────┬─────────┬─────────┬─────────┬─────────┬─────────┐
│   "The"  │"capital"│  "of"   │"Brazil" │  "is"   │ [MASK]  │ [MASK]  │
├──────────┼─────────┼─────────┼─────────┼─────────┼─────────┼─────────┤
│  PROMPT  │ PROMPT  │ PROMPT  │ PROMPT  │ PROMPT  │ OUTPUT  │ OUTPUT  │
│ never    │ never   │ never   │ never   │ never   │ noisy,  │ noisy,  │
│ masked   │ masked  │ masked  │ masked  │ masked  │ refined │ refined │
│          │         │         │         │         │ each    │ each    │
│          │         │         │         │         │ step    │ step    │
└──────────┴─────────┴─────────┴─────────┴─────────┴─────────┴─────────┘

                  ◄──── Bidirectional Attention ────►
                  (all tokens attend to all tokens)

The model sees both prompt and (noisy/masked) output tokens. During each diffusion step, it predicts the denoised version of the output tokens, using the prompt as context. The prompt acts like a fixed anchor that guides the denoising.

Key difference from AR prompting

Property AR (GPT-style) Diffusion (masked)
Prompt attention Causal (can only see past tokens) Bidirectional (can see entire prompt)
Prompt length No limit beyond context window No limit beyond context window
Prompt + output Contiguous (prompt then output) Contiguous (prompt masked-portion)
Prefix-preserving Yes — early tokens never change Yes — prompt tokens stay fixed
Bidirectional attention is actually better for understanding prompts. If your prompt is "The capital of Brazil is", an LM with bidirectional attention can see all 5 words at once and build a richer representation than one that reads left-to-right. This is why BERT-style encoders were better than GPT at understanding tasks (classification, NER) — and diffusion LMs inherit this advantage.

3. Context Window Sizing: Same Constraints, Different Bottlenecks

The context window = prompt tokens + output tokens. The architecture determines the maximum total length. Here's how the same techniques apply:

Technique AR Models Diffusion Models
RoPE / Positional Encodings Supports extrapolation (NTK-aware scaling, YaRN, etc.) to extend beyond training length Same — most diffusion LMs use RoPE. Same extrapolation techniques apply.
Flash Attention Required for long sequences. O(L²) attention handled via tiling. Same — diffusion models also use standard attention and benefit from Flash Attention equally.
KV-cache growth O(L × d_model) — big problem at 128K+ ❌ Not applicable — no KV-cache needed
Full attention memory O(L²) during training; at inference, KV-cache + causal masking helps O(L²) during training AND inference (no causal mask savings)
Sliding window / sparse attention Common (e.g., Mistral's sliding window, LongFormer) Same — can be applied to diffusion LMs
Ring-Attention / sequence parallelism Distributes L² across GPUs Same — can distribute across GPUs

The real bottleneck: total sequence length × diffusion steps

Here's the hidden cost. At inference, an AR model pays the attention cost once per token. A diffusion model pays it per diffusion step. For 64 steps at 128K context:

AR inference on 128K tokens:
  - 128K forward passes, each with O(1) KV-cache-augmented attention
  - Total attention FLOPs: ~O(L²) amortized across passes
  - Memory: KV-cache = 2 × 128K × 4096 bytes ≈ 1 GB

Diffusion inference on 128K tokens (64 steps):
  - 64 forward passes, each with O(L²) full attention
  - Total attention FLOPs: 64 × O(L²)
  - Memory: No KV-cache, but attention matrix for 128K = 16B entries = 64 GB
  - ✅ Flash Attention fixes this (never materializes the full matrix)
  - But FLOPs remain: ~64× more attention compute than AR

So at very long contexts (128K+), AR has a compute advantage because the KV-cache makes per-token attention cheap. Diffusion pays full-attention cost per step.

This is where DiffuMamba's SSM backbone matters: Mamba has O(L) complexity instead of O(L²). So at 128K context:

Transformer diffusion:  64 steps × O(L²) attention  → very expensive
Mamba diffusion:        64 steps × O(L) state scan  → much cheaper

Current context window ceilings (diffusion LMs)

Model Train Context Architecture Max Extrapolated Bottleneck
MDLM 1024 Transformer (DiT) ~2048 (RoPE) Designed for small-scale experiments
SEDD 1024 Transformer (DiT) ~2048 Standard attention bound
LLaDA 4096 Transformer (decoder) ~8192 (RoPE extrapolation) Full attention L² at training time

Key insight: If long context (128K+) is important to you, DiffuMamba's SSM approach is strategically more interesting than DiffusionGemma's transformer approach. The O(L) vs O(L²) scaling makes a massive difference at 128K — especially when multiplied by 64 diffusion steps vs 1 AR pass.

Recipe for Your L40S Context Experiments

If you want to experiment with this on your hardware:

  1. Start with LLaDA (4096 context) — it fits on your L40S in BF16. Prompt it with Portuguese text, over-generate to 4096 tokens, observe quality.
  2. Try DiffuMamba when code is released — the Mamba backbone should handle longer contexts (16K-32K) more efficiently on the same GPU.
  3. Build your tiny model with RoPE — Lesson 0004 (hands-on) will use RoPE, so your tiny model can extrapolate beyond its training length (e.g., train at 256, infer at 512).

Lesson 0002: Why Not Autoregressive?

Estimated time: 25 min · Prerequisites: Lesson 0001

← Feasibility Check Next → Core Mechanics
tl;dr — Autoregressive generation is fundamentally sequential: to generate N tokens you must run N forward passes, one after another. This is not a software bug — it is a structural constraint baked into the "predict the next token" objective. Diffusion models break this chain by generating all tokens in parallel, trading N serial passes for a smaller number of parallel iterations.

The Sequential Bottleneck

Every autoregressive language model — GPT, LLaMA, Gemma, Claude — works the same way at generation time:

  1. Start with a prompt: "The capital of Brazil is"
  2. Run one forward pass → predict token "Brasília"
  3. Append it: "The capital of Brazil is Brasília"
  4. Run another forward pass → predict token "."
  5. Append it: "The capital of Brazil is Brasília."
  6. ...repeat until done

To generate N tokens, you must run N forward passes, each depending on the output of the previous one. There is no way to parallelize this — token 5 cannot be predicted until tokens 1-4 are known.

This is the bottleneck. Not the FLOPs per pass, not the model size — the sequential dependency. Every generation is O(N) serial steps no matter how many GPUs you throw at it.

The Cost Curve

Here's what that sequential dependency costs in practice:

Generation Length AR: Serial Forward Passes Diffusion: Passes (64 steps) Diffusion Advantage
128 tokens 128 64 (adjustable) 2× fewer passes
512 tokens 512 64 8× fewer passes
2048 tokens 2,048 64 32× fewer passes
8192 tokens 8,192 64 128× fewer passes

Each pass is a full forward propagation through the model — transformers, attention, everything. The key insight: diffusion's cost does not grow with sequence length beyond what's needed for quality. You can use 64 steps for a 128-token output or a 8192-token output.

But wait — aren't diffusion passes more expensive? They process all tokens at once (a full sequence matrix), while each AR pass processes a prefix. In practice, a single diffusion pass is roughly equivalent to one AR pass for the full sequence length. So diffusion at 64 steps costs ~64 "full-sequence" passes, while AR at 2048 tokens costs 2048 "prefix" passes. The arithmetic works in diffusion's favor at longer sequences — but the breakeven point depends on model architecture, sequence length, and number of diffusion steps.

The KV-Cache Trick (And Its Limits)

AR models have a clever optimization: the key-value cache. Instead of recomputing attention for all previous tokens each time, they cache the keys and values from earlier forward passes. Each new pass only computes attention for the new token against cached past.

This helps — per-token FLOPs drop from O(L²) to O(L). But it doesn't change the fundamental serial dependency. The cost is now:

  • Time: still O(N) serial steps (each step is cheaper, but still sequential)
  • Memory: O(N × d) for the cache (2 × N × d_model bytes for keys + values)

For a 2048-token sequence with d_model=4096 (a 7B-class model), the KV-cache alone takes ~67 MB per sequence. At batch size 64, that's ~4.3 GB — not negligible, and it grows linearly with sequence length.

Diffusion models need no KV-cache at all. Every forward pass processes the full sequence with bidirectional (or full) attention — no masking, no caching. Your entire VRAM goes to weights and activations.

What Training Looks Like (For Completeness)

Ironically, AR models are trained in parallel using a technique called teacher forcing:

Input:  [The, capital, of, Brazil, is]
Target: [capital, of, Brazil, is, Brasília]
Loss:   cross_entropy(pred, target) across ALL positions simultaneously

The model predicts all next tokens at once — but this only works because the ground truth is known during training. At inference time, there's no ground truth, so you're forced into sequential generation.

Diffusion models are trained and deployed with the same parallel structure. The training objective (predict the original tokens from a corrupted version) mirrors the inference procedure (denoise step by step). There is no train-inference mismatch.

The Essential Trade-Off

Dimension Autoregressive Diffusion
Training parallelism ✅ Full (teacher forcing) ✅ Full (corrupt → predict)
Inference parallelism ❌ Sequential (token by token) ✅ Parallel (all tokens per step)
Cost per inference pass O(L) FLOPs with KV-cache O(L²) FLOPs (full attention)
Number of inference passes L (fixed) N_steps (adjustable, 4-1000+)
Memory overhead KV-cache: O(L×d_model) None (no cache)
Total inference FLOPs O(L²) with causal masking O(N_steps × L²) with full attention

This table reveals something subtle: diffusion isn't strictly cheaper in total FLOPs. 64 steps of full-sequence attention can be more FLOPs than 2048 steps of cached AR generation. The advantage isn't raw FLOPs — it's wall-clock latency and memory efficiency:

  • 64 sequential steps × 50ms per pass = 3.2 seconds
  • 2048 sequential steps × 5ms per pass (with KV-cache) = 10.2 seconds
  • Parallel hardware utilization is often better for large batches of full sequences

Diffusion wins on wall-clock time because passes are parallelizable and don't depend on each other (they depend on the sequence state, which evolves, but all tokens within a pass are computed simultaneously).

Why This Matters for Your L40S

With 48 GB VRAM and no KV-cache overhead, your L40S can run larger diffusion models than AR models at the same batch size. The bottleneck shifts from memory-bandwidth-bound AR generation to compute-bound diffusion passes — a tradeoff that often favors diffusion on datacenter GPUs.

Key takeaway: Autoregressive generation is an inherently serial algorithm. No amount of hardware acceleration can make it parallel — it's like trying to compute Fibonacci recursively in parallel. Diffusion architectures break the serial dependency by predicting all tokens simultaneously, then refining them over multiple passes. The cost is training (16× more compute), the benefit is inference (tunable latency, no KV-cache, long-sequence efficiency).

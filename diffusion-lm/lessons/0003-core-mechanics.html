Lesson 0003: Core Mechanics

Estimated time: 30 min · Prerequisites: Lessons 0001, 0002 · Hardware: none required

← Bridge Note ☰ Context Length → · Next → Masked Diffusion
tl;dr — Diffusion models work by taking clean data, gradually destroying it (forward process), then learning to reverse that destruction (reverse process). For text this is hard because tokens are discrete — you can't "add a little bit of noise" to a word the way you can to a pixel. There are three families of solutions: diffuse in continuous embedding space, transition between discrete tokens, or mask tokens away. Each has different tradeoffs.

The Intuition: Image Diffusion First

Before we touch text, let's build intuition with something visual. Here's how diffusion works for images:

①
Forward pass — Take a photo and gradually add Gaussian noise over many steps (e.g., 1000 steps). At step 0 the image is clear. At step 1000 it's pure random noise. Each step adds a tiny bit more noise according to a variance schedule.
②
Reverse pass — Train a neural network to predict the noise added at each step, given the noisy image and the step number. Starting from pure noise, the network gradually removes noise step by step, recovering the original image.
③
Generation — Once trained, you can sample: start with pure noise (or a random seed), run the reverse process for all steps, and watch a plausible image emerge from nothing.
Forward (fixed, no training) Clean image ──→ x₀ → x₁ → x₂ → ... → x_T (pure noise) ↑ ↑ ↑ ε ∼ N(0,I) per step (you control how much noise per step) Reverse (learned by neural network θ) Pure noise ──→ x_T → x_{T-1} → ... → x₀ (generated image) ↑ p_θ(x_{t-1} | x_t, t) predicted by model
Key insight for later: In image diffusion, the forward process is fixed — you just add noise according to a simple formula. You never train the forward process. The neural network only learns the reverse direction. This means training data is cheap: take any image, add noise at a random timestep, and ask the network to predict the noise. Each image generates infinite training examples at different noise levels.

Why Text Breaks the Image Intuition

Image diffusion works because you can add continuous noise (Gaussian) to pixel values. A pixel at value 0.7 can become 0.72 with a tiny noise addition. The noise is differentiable — small changes in input produce small changes in output, which is exactly what gradient descent needs.

Text tokens are categorical, not continuous. The token "gato" is token ID 1234. What's "gato + 0.02 × noise"? It doesn't make sense. You can't add 2% noise to a token the way you add 2% noise to a pixel. The space of tokens has no geometry — you can't interpolate between "cachorro" and "gato".

Property Image Diffusion Text Diffusion
Data type Continuous (pixel ∈ [0, 1]) Discrete (tokens ∈ {1, 2, ..., V})
Noise type Gaussian (additive, continuous) ??? — Can't add to a token
Forward process x_{t} = √(α_t) x₀ + √(1-α_t) ε Depends on the family (see below)
Loss ‖ε - ε_θ(x_t, t)‖² (MSE on noise) Cross-entropy on predicted tokens
Training data Infinite (any noise level) Infinite (any masking/corruption level)
This is the core challenge. Every diffusion LM approach is fundamentally a solution to the question: "How do I define a 'forward noising process' on discrete tokens that the model can learn to reverse?" The answer defines the architecture.

The Three Solution Families

Researchers have converged on three main strategies. Each makes a different tradeoff between theoretical elegance, training cost, and practical implementability.

⚡ Continuous Embedding Space

Diffusion-LM

The idea: Don't diffuse the tokens themselves. Instead, embed each token into a continuous vector (ℝd), then apply standard Gaussian diffusion in that embedding space. After denoising, project back to the nearest token.

Like: Image diffusion, but on word embeddings instead of pixels.

Downside: The round-trip (embed → noise → denoise → nearest token) introduces rounding errors. There's no guarantee the denoised embedding corresponds to a valid token.

Paper: Diffusion-LM (Li et al., 2022)

Cost note: moderate Standard transformer + embedding layer. Training cost similar to AR of same size, but inference requires many steps.

🔀 Discrete Token Transitions

D3PM / SEDD

The idea: Define a transition matrix Q_t that governs how tokens change into other tokens over time. At each forward step, a token either stays the same or flips to another token according to Q_t. The reverse process learns to undo these transitions.

Like: A Markov chain on the vocabulary. Each token has a probability of mutating into any other token, controlled by the timestep.

Downside: The transition matrix is |V| × |V| (vocabulary size squared). For a 50K vocabulary that's 2.5B entries — you need clever parameterization (e.g., uniform transitions). Training is also more complex than the masked approach.

Papers: D3PM (Austin et al., 2021), SEDD (Lou et al., 2024)

Cost note: higher More complex loss (score entropy vs simple cross-entropy). SEDD medium (320M) requires 8× A100s for days.

⬜ Masked Diffusion

MDLM / LLaDA

The idea: The forward process gradually replaces tokens with a special [MASK] token. At step 0, all tokens are revealed. At step T, all tokens are [MASK]. The model learns to predict the original tokens from the masked version.

Like: BERT's masked language model, but applied iteratively with a noise schedule instead of a single pass.

Downside: Simpler than D3PM, but the [MASK] token carries no information — once masked, all identity is lost. Compare to discrete transitions where a token might mutate to a "similar" token, carrying some signal.

Papers: MDLM (Sahoo et al., 2024), LLaDA (2025)

Cost note: lower This is the practical starting point. Simple objective (cross-entropy on masked tokens). MDLM's code runs on a single GPU. Lesson 0004 covers this in depth, and Lesson 0005 builds one from scratch.

The Training Loop (Any Family)

Despite the differences, all three families share the same training structure:

  1. Sample a random timestep t ∈ [0, T]
  2. Corrupt the input according to the forward process at timestep t (add noise, transition, or mask)
  3. Predict the reverse: feed the corrupted input + timestep t into the neural network, and ask it to predict the clean version (original tokens or noise)
  4. Compute loss (cross-entropy or MSE) against the ground truth
  5. Backpropagate gradients through the network
  6. Repeat for millions of steps
# Pseudocode — identical structure regardless of family
for batch in dataloader:
    x_0 = batch.tokens                     # Clean input (shape: [B, L])
    t = random_timesteps(B)                # Random timesteps per sample

    # Forward process (no training — fixed formula)
    x_t = corrupt(x_0, t)                  # Depends on family

    # Neural network predicts the reverse
    prediction = model(x_t, t)             # model: noise_predictor or token_predictor

    # Loss depends on what the model predicts
    if family == 'continuous':
        loss = mse(prediction, noise)      # Predict the noise
    elif family == 'masked':
        loss = cross_entropy(prediction, x_0[masked_positions])
    elif family == 'discrete':
        loss = score_entropy(prediction, x_0, x_t)

    loss.backward()                        # ← This is where the 16× compute gap comes from
    optimizer.step()
Why diffusion training is more expensive (deeper explanation): In AR training, every token in the sequence serves as both input and target simultaneously (teacher forcing). A 1024-token sequence gives you 1024 training signals from one forward pass. In diffusion training, a 1024-token sequence at noise level t gives you only the signal at that specific noise level — you need to show the model many different noise levels to teach it the full denoising trajectory. Hence the 16× compute multiplier (SMDM).

The Sampling Process (Inference)

Once trained, sampling works like this:

  1. Initialize a canvas of length L with pure noise / all [MASK] / random tokens (depending on family)
  2. For t = T down to 1:
    • Feed the current state x_t into the model
    • Get the model's prediction of the clean data
    • Partially denoise: compute x_{t-1} from x_t and the prediction, using the known noise schedule
  3. Return x₀ — the final denoised sequence

The number of steps T is a free parameter you set at inference time. More steps = better quality (but more compute). Fewer steps = faster generation (but lower quality). This is the compute-quality tradeoff that makes diffusion LMs unique.

Key advantage over AR: In AR inference, you must do L steps. In diffusion inference, you choose how many steps to take — and it's independent of L. A 128-step diffusion generates 128 tokens or 8192 tokens in the same number of passes.

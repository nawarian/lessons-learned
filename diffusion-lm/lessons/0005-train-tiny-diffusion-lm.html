The Code

The training script is at 📄 code/train_tiny_mdm.py — a single self-contained Python file. Let's walk through every section.

1 Setup & Configuration

The Config class holds all hyperparameters. You can change any of them:

class Config:
    vocab_size: int = 64       # chars + [MASK] + [PAD] + [BOS]
    d_model: int = 128         # embedding dimension
    n_layers: int = 4          # transformer layers
    n_heads: int = 4           # attention heads
    d_ff: int = 512            # feed-forward hidden dim
    max_seq_len: int = 128     # max characters per sample
    batch_size: int = 64
    lr: float = 3e-4
    train_steps: int = 3000
    num_inference_steps: int = 64
    inference_temp: float = 0.8
    device: str = "cuda" if torch.cuda.is_available() else "cpu"

2 Cosine Masking Schedule

The forward process uses a cosine schedule — same as MDLM and LLaDA:

def cosine_mask_schedule(t):
    """t in [0, 1], returns masked fraction α(t) ∈ [0, 1]"""
    return 1 - cos(π/2 · t)

At t=0 (no corruption): α=0 → 0% masked.
At t=1 (full noise): α=1 → 100% masked.
Cosine makes α grow slowly at first, then rapidly, then taper — exposing the model to a wide range of masking levels.

The get_mask() function samples which positions to mask given α(t): each sample in the batch gets exactly α(t) · seq_len random positions masked.

3 Character Tokenizer

No subword tokenizers needed — we work at the character level:

class CharDataset(Dataset):
    def __init__(self, text, seq_len):
        chars = sorted(set(text))          # ~58 unique chars
        self.stoi = {ch: i+3 for i,ch in enumerate(chars)}
        self.itos = {i+3: ch for ch in chars}
        self.itos[0] = '[MASK]'            # token 0 = [MASK]
        self.itos[1] = '[PAD]'             # token 1 = [PAD]
        self.itos[2] = '[BOS]'             # token 2 = [BOS]

Reserved IDs: 0=[MASK], 1=[PAD], 2=[BOS]. Actual characters start at ID 3. This gives us a vocabulary of ~60 tokens.

4 The Model Backbone

The core architecture: a standard transformer encoder with time conditioning:

class MDMBackbone(nn.Module):
    def __init__(self, cfg):
        self.token_embed = Embedding(vocab_size, d_model)
        self.pos_embed   = Embedding(max_seq_len, d_model)
        self.time_embed  = SinusoidalEmbedding → MLP → scale + shift
        self.transformer = TransformerEncoder × 4 layers
        self.head        = Linear(d_model, vocab_size)

    def forward(self, x, t):
        # x: [B, L] token IDs (with [MASK]=0)
        # t: [B] noise levels in [0, 1]
        h = token_embed(x) + pos_embed
        t_emb = time_embed(t)              # → scale, shift for adaLN
        h = h * (1 + t_scale) + t_shift    # modulate with noise level
        h = transformer(h)                 # bidirectional attention
        return head(layer_norm(h))         # [B, L, V] logits

The time embedding is crucial — it tells the model what noise level it's seeing. The model learns different denoising strategies for different masking levels. At low t (few masks), it mostly fills in confident tokens. At high t (many masks), it predicts structure from sparse context.

5 Training Step

This is the heart of the algorithm — and it's remarkably simple:

def train_step(model, optimizer, x0):
    B, L = x0.shape

    # 1. Sample random noise level per sample
    t = torch.rand(B)                    # uniform in [0, 1]

    # 2. Corrupt: mask α(t) fraction of tokens
    alpha = cosine_fn(t)                 # [B]
    n_mask = (alpha * L).long()          # how many tokens to mask
    mask = random_mask(n_mask)           # [B, L] boolean
    x_t = x0.clone()
    x_t[mask] = MASK_TOKEN_ID

    # 3. Predict original tokens
    logits = model(x_t, t)               # [B, L, V]

    # 4. Loss: cross-entropy on MASKED positions only
    loss = cross_entropy(logits[mask], x0[mask])

    loss.backward()
    optimizer.step()

Key insight: Every training step sees a different random masking level. Over thousands of steps, the model learns to predict tokens at any corruption level — from nearly clean to nearly all-masked. This is what makes iterative denoising work at inference time.

6 Inference (Generation)

Generation is the reverse of training — start from all-masked and iteratively reveal:

def generate(model, num_steps=64, temperature=0.8):
    # Start from all [MASK]
    tokens = [MASK] × seq_len

    for step in range(num_steps):
        t = 1.0 - (step / num_steps)      # noise level decreases
        logits = model(tokens, t)          # forward pass
        probs = softmax(logits / temp)     # sample with temperature
        sampled = sample(probs)            # [L]

        # How many to reveal this step?
        α_now  = cosine_fn(t)
        α_next = cosine_fn(t - 1/num_steps)
        n_reveal = ceil((α_now - α_next) × L)

        # Reveal highest-confidence masked positions
        is_masked = (tokens == MASK)
        conf = max_probs[is_masked]
        reveal = top_k(conf, n_reveal).indices
        tokens[reveal] = sampled[reveal]

    return tokens

The confidence-based unmasking is the key trick: at each step, the model reveals its most confident predictions first. Those revealed tokens become context for the next step, helping the model predict the harder positions.

What Success Looks Like

You'll know the model trained correctly when:

  • ✅ Loss drops steadily from ~3.0 → ~1.0 over 3000 steps
  • ✅ Generated text contains valid character patterns (English-like letter sequences, common bigrams like "th", "he", "an")
  • ✅ Different --temp values produce different diversity levels (low=repetitive, high=chaotic)
  • ✅ Generation with a prompt starts with that prompt prefix
  • ✅ Saved model reloads with --infer and produces similar quality

Experiments to Try

Once the basic training works, try these modifications to build intuition:

Experiment Change What to observe
Fewer inference steps cfg.num_inference_steps = 8 Generates faster but worse quality — tokens appear more random, less coherent structure
More inference steps cfg.num_inference_steps = 256 Better quality but slower. Diminishing returns after ~64 steps for this tiny model
Higher temperature cfg.inference_temp = 1.5 More diverse but more errors — rare characters appear, less structured output
Uniform schedule Replace cosine_fn with t Slower convergence — loss drops more slowly, generation quality degrades
Deeper model cfg.n_layers = 8 Better quality but slower training. ~4.5M params, ~3 GB VRAM
Longer context cfg.max_seq_len = 256 More coherent longer-range structure but VRAM usage doubles
⚠ VRAM budget: The default config uses ~1.5 GB VRAM. Each doubling of sequence length doubles VRAM (attention is O(L²) without Flash Attention). On your 8 GB local GPU, max_seq_len=256 is fine. On the L40S (48 GB), you can push to 512 or 1024.

What the Loss Curve Tells You

Loss during training tracks predictive accuracy on masked tokens. A loss of:

  • ~3.0: Random guessing (vocab=62, randomly guessing has loss ln(62) ≈ 4.1; 3.0 means the model has started learning)
  • ~2.0: The model can predict common characters (space, 'e', 't', 'a') but struggles with rare ones
  • ~1.5: The model has learned character n-gram statistics — knows "th" → "e", "qu" → "e"/"i"
  • ~1.0: Near-optimal for this tiny model — captures most character-level patterns in Shakespeare
Your L40S upgrade path: This tiny model validates the algorithm on any GPU. On your L40S (48 GB), you can scale to:
  • BPE tokenizer with 8K-16K vocab (mirroring the Portuguese-optimized plan from Learning Record 0002)
  • 256-512 sequence length with batch size 32-64
  • 8-12 transformer layers (~10-15M params)
  • Train on Portuguese text for ~4-8 hours to get a functional character diffusion LM
The algorithm is exactly the same — only the scale changes.

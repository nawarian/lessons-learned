Reference · Provenance & Removal

Where did this come from?

One command's path tells you who installed it — and how to remove it cleanly.

The four sources at a glance

SourceTypical locationOwned by dpkg?Clean removal
apt / dpkg/usr/bin, /usr/lib, /usr/sbinYesapt purge NAME then apt autoremove
snap/snap/bin/X → /snap/… (squashfs)Nosnap remove NAME
make install/usr/local/{bin,lib,…}, sometimes /optNo (real files)make uninstall · install manifest · stow
manual symlink/usr/local/bin/X → elsewhereNo (a symlink)Delete link; remove target dir / stow -D

The decision procedure

1.  command -v X            # is it even on PATH? get the path
2.  readlink -f "$(command -v X)"   # resolve every symlink to the real file
3.  ls -l "$(command -v X)"         # is the PATH entry itself a symlink? where to?

    ── classify by the resolved path ──
    /snap/...           → SNAP            → snap remove X
    else:
4.  dpkg -S "$(readlink -f "$(command -v X)")"
    prints a package   → APT/DPKG        → apt purge / apt remove
    "no path found"    → UNMANAGED, and:
       PATH entry is a symlink     → MANUAL SYMLINK  → rm the link (+ target)
       PATH entry is a real file
         under /usr/local or /opt  → MAKE INSTALL    → uninstall manifest / stow

FHS landmarks that matter here

PathWho writes itMeaning
/usr/bin /usr/libthe distro (apt)Distribution-managed. Don't hand-edit. dpkg owns these.
/usr/localyouLocal installs the package manager will never touch. Mirrors /usr (bin lib sbin share).
/opt3rd-party / youSelf-contained blobs, one dir per app (/opt/foo/…).
/snapsnapdRead-only squashfs mounts, one per snap revision.
/etcdistro + youConfig. apt remove leaves it; apt purge deletes it.
/varprogramsMutable state: logs, spool, /var/lib/snapd (snap data & blobs).
The one-line rule. If dpkg -S claims the file, apt owns it. If the path starts with /snap, snapd owns it. If it sits in /usr/local or /opt and dpkg disclaims it, you own it — and the difference between a symlink and a real file there tells you whether it came from a manual link or a make install.

Inspecting an apt package's full footprint

dpkg -L NAME      # every file the package installed (so nothing is missed)
dpkg -l 'pat*'    # list installed packages matching a glob
apt-cache rdepends NAME   # what depends on it (before you yank it)

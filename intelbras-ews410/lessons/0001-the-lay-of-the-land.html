Lesson 1 · EWS 410

The Lay of the Land

What your lamp actually is, how local control works, and finding it on your network — your first tangible win.

By the end of this lesson you will:
  • Know the mental model for controlling the lamp without the vendor cloud.
  • Have tinytuya installed.
  • Have run a LAN scan that finds your bulb — its IP and device ID printed on your screen.

1 · It isn't really an "Intelbras" lamp

The EWS 410 is sold as Intelbras and configured with the Izy Smart app, but under the hood it's a Tuya device. Izy/Mibo Smart is Intelbras's rebrand of the Tuya platform — the same silicon and protocol used by dozens of brands (Positivo, Multilaser, Smart Life…).[refs] That's the single most useful fact in this whole course, because it means a large, mature, open-source toolchain already speaks your lamp's language.

Two radios, two jobs:

  • Wi-Fi 2.4 GHz — how the lamp is controlled. This is what we'll use.
  • Bluetooth 4.2 — used only to provision (hand the lamp your Wi-Fi credentials during setup). Not a day-to-day control channel. So "over Wi-Fi/Bluetooth" in practice means: control = Wi-Fi.

2 · The mental model: cloud vs. local

When you tap a button in Izy Smart, the normal path is:

phone  →  Tuya cloud  →  your bulb        (the vendor "API" path)

Every Tuya bulb also speaks a local LAN protocol directly, with no cloud in the loop:

your controller  →  bulb on the LAN (TCP port 6668, AES-encrypted)   ← what we build

This local channel is exactly what your agentic harness should use: fast, private, works offline. To open it you need three secrets:

SecretRoleWe get it in…
Device IDWhich deviceLesson 1 (this scan)
IP addressWhere on the LANLesson 1 (this scan)
Local keyAES key to decrypt the trafficLesson 2
The honest boundary. "Without their API" means no cloud at control time. Today's scan is 100% local. The local key in Lesson 2 is the one step that — done the easy way — reads from Tuya's cloud once. After that, never again. A fully-offline key route exists too; we'll cover it as the harder option.

3 · Install the toolchain

We'll use tinytuya — the reference Python tool for direct-LAN Tuya control. In a fresh virtualenv:

python3 -m venv ~/.venvs/tuya
. ~/.venvs/tuya/bin/activate
pip install tinytuya

4 · Your win: find the bulb

Make sure the lamp is powered on and your computer is on the same 2.4 GHz network as the lamp (not a separate guest/IoT VLAN). Then:

python -m tinytuya scan

tinytuya sends a UDP broadcast; Tuya devices announce themselves. You should see a block like:

Device Found:
  Address: 192.168.0.42     ← the IP   (secret #2)
  Device ID: bf1a2b3c...    ← the gwId (secret #1)
  Version: 3.3              ← protocol version (note this — matters in Lesson 3)
  Local Key: (need to run wizard)   ← secret #3, coming in Lesson 2

Two of the three secrets, captured in one command — and you can see the lamp is reachable on its local protocol. Write down the Device ID, IP, and Version.

If scan finds nothing: the usual cause is that your controller and the bulb are on different subnets/VLANs, or UDP broadcast is filtered. Confirm the lamp works in the app first (proves it's online), then check you're on the same SSID. See the failure table in the cheat sheet.

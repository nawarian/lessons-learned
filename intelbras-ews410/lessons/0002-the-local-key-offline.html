Lesson 2 · EWS 410

The Local Key, Offline

The third secret — read straight out of your phone, no cloud account, no developer API.

By the end of this lesson you will:
  • Understand why the key can only be read, never computed — and where it lives.
  • Locate the Intelbras app's key cache file on your phone.
  • Extract device-ID → local-key pairs for both your bulbs with a tiny parser.
  • Have a devices.json ready for Lesson 3's first local command.

1 · The one idea that makes this make sense

A Tuya local key is a random 16-character value the cloud generates when the bulb is paired. It is not derived from the device ID, the MAC, or anything you can see on the wire. So there is no algorithm to "crack" — every method of *getting* the key is really a method of reading it from somewhere it is already stored:

Where the key is storedHow you'd read itCloud?
Tuya's serversDeveloper API wizardYes — rejected
Your phone's app cacheRead the app's data fileNo (this lesson)
In-flight app trafficmitmproxy captureIntercepted by you; fragile
Nowhere (replaced)Reflash ESPHome/LibreTinyNever — but invasive
Why your phone has it. The Intelbras/Izy app doesn't only go through the cloud — it also controls bulbs directly on your LAN, which means it must keep each bulb's local key on the phone. It's cached in cleartext. We just read it.

2 · Find the key cache file

The Intelbras app is built on the Tuya SDK, so it uses Tuya's storage layout. On Android the file lives under the app's private data directory:

# modern app versions (MMKV binary store):
/data/data/<package>/files/thingmmkv/preferences_global_key

# older app versions (XML):
/data/data/<package>/shared_prefs/preferences_global_key<digits>.xml

<package> is the Intelbras app's package name (something like br.com.intelbras.… or com.tuya.smartlife). You don't need to guess — when you open the app's data folder, you'll see it. If unsure, list packages:

adb shell pm list packages | grep -iE 'intelbras|izy|tuya|smart'

Now copy that one file off the phone, using whatever access you already have to the app's data folder. Common ways (any one is enough):

  • File-manager with access → copy it to /sdcard/, then move it to your PC.
  • adb (if the app data is reachable): adb pull /data/data/<package>/files/thingmmkv/preferences_global_key .
  • adb run-as (debuggable builds): adb shell run-as <package> cat files/thingmmkv/preferences_global_key > key.mmkv

The file is small. You only need a copy on your computer — don't modify the original.

3 · Extract the keys

Whether the file is MMKV-binary or XML, the device records inside are cleartext JSON — each contains a devId and its localKey. MMKV isn't encrypted by default, so we can pull the pairs out without a full parser. Save this as extract_keys.py:

import re, sys

blob = open(sys.argv[1], 'rb').read().decode('latin-1', 'ignore')

# Anchor on each 16-char localKey, then find the devId & name in the same record.
for m in re.finditer(r'"localKey":"(\w{16})"', blob):
    key = m.group(1)
    window = blob[max(0, m.start() - 2000): m.start() + 2000]
    dev  = re.search(r'"devId":"(\w{18,25})"', window)
    name = re.search(r'"name":"([^"]{1,40})"', window)
    print(f'{dev.group(1) if dev else "?":24}  {key}  {name.group(1) if name else ""}')

python extract_keys.py preferences_global_key

You should get two lines — one per bulb — like:

eb402aa51227ed67cbnwj4    a1b2c3d4e5f60718    Sala
eba18068361d2cd57fbkwv    9f8e7d6c5b4a3210    Quarto
Cross-check against your scan. The device IDs must match the ones from Lesson 1's scan — eb402aa51227ed67cbnwj4 (192.168.1.16) and eba18068361d2cd57fbkwv (192.168.1.17). If a devId from the file has no match on your LAN, it's a different device on your account — ignore it.

4 · Assemble devices.json — the win

Combine the three secrets per bulb into the file tinytuya reads. Hand-write it (no wizard needed):

[
  { "name": "sala",   "id": "eb402aa51227ed67cbnwj4",
    "key": "PASTE_KEY_1", "ip": "192.168.1.16", "version": "3.5" },
  { "name": "quarto", "id": "eba18068361d2cd57fbkwv",
    "key": "PASTE_KEY_2", "ip": "192.168.1.17", "version": "3.5" }
]

That's the third secret captured with zero cloud API. You now hold everything needed to talk to both bulbs locally — which is exactly what Lesson 3 does.

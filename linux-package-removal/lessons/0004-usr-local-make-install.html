Lesson 4 · Decluttering Linux

The /usr/local Problem

A make install copies files everywhere and tells nobody. No ledger exists. Here's how to uninstall one anyway — and never create the problem again.

The win: you'll be able to remove a source-built program that has no make uninstall, three ways depending on what you have left — and you'll know the one habit (Stow) that makes every future source install a one-command uninstall.

Why this is the hard case

apt and snap both keep ledgers. make install keeps none — it's just a recipe that runs cp and install into /usr/local (and sometimes /etc, /var…). [w3tutorials] That's exactly why Lesson 1 classified these by elimination: a real file in /usr/local that dpkg disclaims. Recall the /usr vs /usr/local boundary — the package manager never writes the latter, so everything there is yours to account for.

Three routes, best-to-worst by what you kept

1. The build directory still exists

Try the uninstall target — many projects have one, some don't advertise it:

make -n uninstall      # dry run: preview what it WOULD remove
sudo make uninstall    # if the target exists

make -n first is the safety move — if the target is missing you'll see "No rule to make target 'uninstall'" instead of guessing. [w3tutorials]

2. No uninstall target, but you can re-run install

Capture the manifest the install would write, then delete exactly those paths:

# Re-run install but record every destination file:
sudo make install DESTDIR=/tmp/manifest   # stages files under /tmp/manifest
find /tmp/manifest -type f -o -type l |
  sed 's#/tmp/manifest##' > files.txt      # the real install paths
# inspect files.txt, then:
xargs -a files.txt sudo rm -v

Many GNU autotools builds also drop an install_manifest.txt (CMake always does) — if you see one, xargs -a install_manifest.txt sudo rm is the whole job.

3. Nothing left — only the installed files on disk

Reconstruct the footprint by hand. You classified the binary in Lesson 1; now map its neighbours. For a program foo installed under --prefix=/usr/local, the usual suspects are /usr/local/bin/foo, /usr/local/lib/libfoo*, /usr/local/include/foo*, /usr/local/share/foo/, and /usr/local/share/man/man1/foo*. List, verify each is unowned, then remove: 

for p in /usr/local/bin/foo /usr/local/lib/libfoo* \
         /usr/local/include/foo* /usr/local/share/foo; do
  dpkg -S "$p" 2>/dev/null || echo "UNOWNED: $p"   # confirm before deleting
done

This is the messy route — Lesson 5 covers tooling (cruft) to find unowned files systematically.

Never again: install future source builds through GNU Stow. Build with ./configure --prefix=/usr/local/stow/foo-1.2, run make install into that isolated tree, then cd /usr/local/stow && sudo stow foo-1.2 to symlink it into /usr/local. To uninstall: sudo stow -D foo-1.2 removes every symlink, and deleting the one directory removes the files. One app = one directory = trivial removal. [Hetzner]

Prefer apt's tooling? CheckInstall wraps make install, records every file it touches, and builds a real .deb — so the source build becomes removable with apt purge like anything else.

Do this on your own machine

List the binaries you've put in /usr/local and confirm none are apt's:

ls /usr/local/bin
for f in /usr/local/bin/*; do dpkg -S "$f" 2>/dev/null || echo "UNOWNED: $f"; done

Every UNOWNED line is a manual/source install. Pick one, figure out which of the three routes fits, and bring it here before you delete anything.

Primary source: the GNU Stow manual (the "Introduction" + "Terminology" sections) — the cleanest mental model for managing /usr/local by hand.

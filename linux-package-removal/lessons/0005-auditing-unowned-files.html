Lesson 5 · Decluttering Linux

Auditing Unowned Files

The capstone. Instead of investigating one command at a time, sweep the whole system for files no package manages — and for distro files that were quietly modified.

The win: you'll turn the per-command detective work of Lesson 1 into a systematic audit: list everything dpkg doesn't own, verify nothing distro-managed was tampered with, and read the results without panicking at the false positives.

Two complementary questions

A real audit asks both, and they use different tools:

QuestionToolWhat it answers
"What's here that no package owns?"cruftFinds unmanaged files — your manual installs, leftovers, true cruft. [Debian]
"Were any distro files changed or lost?"debsums / dpkg --verifyCompares installed files to dpkg's recorded checksums. [Debian Wiki]

Finding unowned files with cruft

sudo apt install cruft
sudo cruft 2>/dev/null              # report files no package owns

cruft walks the filesystem, asks dpkg about each path, and lists what nobody claims. Expect heavy false positives — your home dir, /var runtime state, caches, logs and device nodes all legitimately belong to no package. The signal you want is concentrated in /usr/local, /opt, and stray files in /usr/bin. Narrow it: 

sudo cruft 2>/dev/null | grep -E '^\s*/usr/local|^\s*/opt'
cruft is a lead generator, not a verdict. Everything it prints is "unmanaged," but unmanaged ≠ deletable — much of it is data you want. Treat each hit as a question ("what is this, did I install it?"), and confirm provenance with the Lesson 1 procedure before removing anything.

A no-install alternative

If you'd rather not add cruft, you can hand-roll the same idea for a directory:

# every real file under /usr/local that dpkg disclaims:
find /usr/local -type f 2>/dev/null | while read -r f; do
  dpkg -S "$f" >/dev/null 2>&1 || echo "$f"
done

Slower and noisier than cruft, but zero new packages and easy to scope to exactly the tree you care about.

The other half: verify distro files with debsums

sudo apt install debsums
sudo debsums -c       # report files whose checksum CHANGED
sudo debsums -ec      # only CHANGED config files (the usual interest)
sudo dpkg --verify    # built-in equivalent, no extra package

debsums compares each installed file to the md5sum dpkg recorded at install time. [Debian Wiki] A changed config you edited is expected; a changed binary you didn't touch is worth investigating. Note some packages ship no md5sums — those report as "no md5sums", not as errors.

Lesson 3 · Decluttering Linux

snap — Where the Bytes Hide

snaps don't live where apt packages live, and old revisions silently pile up gigabytes. Here's the whole mental model, and how to reclaim the space.

The win: you'll understand why du on /snap "lies", where snap data actually sits, how to remove a snap cleanly, and how to delete the stale revisions that quietly eat 2–4 GB.

A different model from apt

An apt package scatters files across /usr/bin, /usr/lib, /etc… A snap does the opposite: each app is a single read-only squashfs image, mounted at a versioned path. That's why Lesson 1 could classify a snap from the path alone — it starts with /snap.

PathWhat's there
/snap/bin/XThe command on your PATH — a shim into the mounted image.
/snap/<name>/<rev>/The mounted, read-only squashfs for one revision.
/var/lib/snapd/snaps/The actual .snap image files on disk — including old revisions. [It's FOSS]
~/snap/<name>/ & /var/snap/Per-user and system data the app writes.
Why du -sh /snap looks huge but freeing it does nothing: /snap/<name>/<rev> is a mount of a squashfs image — du counts the mounted contents, but the bytes physically live once in /var/lib/snapd/snaps/. To see real disk pressure, look there, or at df -h | grep snap for the mounts.

The revision pile-up

snapd keeps old revisions around so it can roll back. By default it retains a couple per snap — but over months that's gigabytes of disabled images. [It's FOSS] 

snap list                 # installed snaps (current revision)
snap list --all           # ALSO shows old/disabled revisions
df -h | grep snap         # the squashfs mounts, with sizes
sudo du -sh /var/lib/snapd # true on-disk weight of snapd

In snap list --all, lines marked disabled are the reclaimable old revisions.

Removing cleanly

sudo snap remove NAME                       # remove a snap (keeps a snapshot)
sudo snap remove NAME --purge               # remove WITHOUT keeping a data snapshot
sudo snap remove NAME --revision=<rev>       # drop one specific old revision
  • Plain snap remove unmounts the image, removes it, and — by default — keeps a snapshot of the app's data (so you could reinstall and restore). That snapshot is itself disk you may not want.
  • --purge skips the snapshot entirely. Use it when you're sure you won't reinstall. [It's FOSS]
  • --revision targets one disabled revision without touching the current one.

To set a global cap so old revisions auto-prune: sudo snap set system refresh.retain=2 (minimum 2).

Do this on your own machine

snap list --all | grep disabled     # the old revisions you can reclaim
df -h | grep snap | head            # see the mounts and their sizes

Each disabled line is safe to drop with sudo snap remove <name> --revision=<rev>. Then set sudo snap set system refresh.retain=2 so they don't pile up again.

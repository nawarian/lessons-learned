apt Removal, Done Right

You classified it as apt in Lesson 1. Now remove it so nothing — binary, config, or orphaned dependency — is left behind.

The win: you'll know exactly which of remove, purge, and autoremove to reach for, why "remove" alone is what leaves cruft, and how to see a package's full footprint before you pull it.

Three verbs, three different jobs

The single biggest misconception: that apt remove "uninstalls" a package. It removes the program files — and deliberately leaves two things behind.

CommandRemoves binaries/libs?Removes its config in /etc?Removes pulled-in deps?
apt remove PKGYesNoNo
apt purge PKGYesYesNo
apt autoremove——Yes (orphans only)

So the two sources of "I uninstalled it but stuff is still here":

  • Config residue. remove keeps /etc files (and the package shows as rc in dpkg -l — removed, config remains). purge is what deletes them. [It's FOSS]
  • Orphaned dependencies. Install apache and it drags in a dozen libraries. Remove apache and those libraries stay until you run apt autoremove. [It's FOSS]
The clean-removal one-liner: sudo apt purge PKG && sudo apt autoremove --purge. Purge removes the package and its config; autoremove --purge then sweeps the now-orphaned dependencies and their configs too.

Look before you leap: the footprint

Before removing anything non-trivial, ask two questions of dpkg's ledger (dpkg-query(1)): 

dpkg -L nginx              # every file this package put on disk
apt-cache rdepends nginx   # what would break if it vanished (reverse-deps)
dpkg -l 'nginx*'           # status of matching packages (ii / rc / un)

dpkg -L is your guarantee that nothing is missed — it's the authoritative manifest apt itself uses. The leading status codes from dpkg -l are worth memorising:

CodeMeans
iiinstalled, fully.
rcremoved, but config files remain — a purge target.
ununknown / not installed.

To sweep up every config-residue package at once: dpkg -l | awk '/^rc/{print $2}' | xargs -r sudo apt purge -y.

One caution before you sweep

apt autoremove trusts the "automatically installed" flag. Occasionally a package you actually want got that flag and would be swept. Always read the list autoremove prints before confirming. If you want to keep something, sudo apt-mark manual PKG protects it. The "don't just autoremove" warning is exactly this: skim, then confirm.

Do this on your own machine

Find your config-residue packages — the quietest, easiest cruft to clear:

dpkg -l | awk '/^rc/ {print $2}'

Anything listed is a package you already removed that left config behind. Inspect one, then purge what you recognise: sudo apt purge <name>. Bring the list here if you're unsure about any entry.

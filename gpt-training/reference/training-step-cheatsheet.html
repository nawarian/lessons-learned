Reference

The Training Step

Forward pass → loss → backward pass → update. The four moves that repeat every batch.

The cycle

forward pass loss backward pass update ─────────── ──── ───────────── ────── logits = model(x) loss = F. loss.backward() optimizer.step() cross_entropy ↓ ↓ autograd records (logits, y) fills every nudges every weight the graph ──────► one scalar ───► p.grad with ─────► opposite its grad ∂loss/∂weight (AdamW sets size) └──────────────── repeat for every batch, every epoch ────────────────┘

The canonical loop body

logits = model(x)                                   # forward pass
loss   = F.cross_entropy(logits.view(-1, V), y.view(-1))
optimizer.zero_grad()                               # clear stale gradients
loss.backward()                                     # backward pass
optimizer.step()                                    # update weights

Order is fixed: forward → loss → zero_grad → backward → step. You can't grade an exam you never took, and you can't step before you know the direction.

Glossary

Forward pass (forward propagation)
Running input through the model to get a prediction. Defined in your forward() method. Side effect: autograd records the computation graph.
nn.Module
Base class for anything with learnable weights. Auto-registers parameters, handles .to()/.train()/.eval(), and wraps forward() in __call__.
model(x) vs model.forward(x)
Always use model(x). It runs __call__ (hooks + bookkeeping) and then your forward(). Calling forward() directly skips the wrapper.
Computation graph
The map autograd builds during the forward pass: which tensor came from which operation on which inputs. The trail backward() walks in reverse.
Logits
The raw output of model(x): shape (B, T, VOCAB_SIZE) — one unbounded score per vocabulary entry, at every position. Not probabilities and not weights. Weights are the machinery; logits are what comes out of it.
Softmax
Turns a row of logits into a probability distribution (each in [0,1], summing to 1). Applied at inference (generate()); cross_entropy applies it internally during training.
Causal mask
The torch.tril triangular mask in attention that blinds each position to its future. Lets one forward pass predict the next char at every position in parallel without any position peeking at its own answer.
Teacher forcing
Training trick: feed the true sequence and predict each next char in parallel (targets = inputs shifted left by one). Possible only in training, where answers are known; generation runs one position at a time.
Loss
A single scalar measuring how wrong the predictions are. The root of the graph and the quantity we minimize. Here: cross-entropy over all B×T positions.
Backward pass (backpropagation)
loss.backward() — walks the graph in reverse, applying the chain rule, to fill each p.grad. Computes directions only; changes no weights.
Gradient (p.grad)
∂loss/∂weight: how much, and in which direction, the loss responds to nudging that weight. An arrow pointing uphill on the loss landscape.
optimizer.zero_grad()
Clears .grad before the backward pass. PyTorch accumulates gradients by default; skip this and stale gradients pile up.
optimizer.step()
Applies the update: each weight moves opposite its gradient. The optimizer (AdamW) sets the actual step size using the learning rate, momentum, and per-weight scaling.
torch.no_grad()
Context manager that switches off graph recording. Use during inference/generation and validation — you don't need gradients there, and skipping them saves memory and time.

Common pitfalls

SymptomLikely cause
p.grad is NoneYou looked before backward() ran, or used torch.no_grad().
Loss erratic / divergingMissing optimizer.zero_grad() — gradients accumulating across steps.
No learning at allForgot optimizer.step(), or the optimizer never got model.parameters().
"element 0 ... does not require grad"Calling backward() inside a no_grad() block, or on a detached tensor.
